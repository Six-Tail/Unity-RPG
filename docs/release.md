# 출시 준비 (Windows · Android · iOS 동시 출시)

번들 ID `com.sixtail.stellaanchor` · 회사 `Six-Tail` · 이름 `스텔라 앵커` · Windows는 직접 배포(zip).

## 메뉴 Tools ▸ 출시 ([ReleaseTools.cs](../Assets/_Project/Scripts/Editor/ReleaseTools.cs))

| 메뉴 | 하는 일 |
|---|---|
| 1. 출시 설정 적용 | 회사 · 이름 · 번들 ID(3플랫폼), 가로 화면만, 안드로이드 IL2CPP · ARM64 · aab · 최신 대상 API · 노치 부분 그리지 않음 · 큰 리소스 애셋 팩 분리, iOS 13 이상, PC 전체 화면(창 크기 조절 · 백그라운드 실행). ProjectSettings에 저장(커밋은 직접 결정) |
| 2. 버전 올리기 | 1.0.0 → 1.0.1, 빌드 번호(안드로이드 versionCode · iOS build) +1. 스토어에 올릴 때마다 |
| 3. Windows 빌드 (zip) | `Builds/Windows/스텔라 앵커.exe` → `Builds/StellaAnchor-Windows-{버전}.zip`(디버그 기호 폴더 제외) |
| 4. Android 빌드 (aab) | `Builds/Android/StellaAnchor-{버전}.aab` — 구글 플레이 업로드용. 출시 키스토어가 없으면 경고 |
| 5. Android 테스트용 apk | 휴대폰에 바로 설치해 보는 용도 |
| 6. iOS 빌드 (Xcode 프로젝트) | `Builds/iOS` → Mac의 Xcode에서 서명 · Archive · App Store Connect 업로드 |
| 출시 화면 미리보기 | 에디터에서도 테스트 기능을 숨겨 출시 화면 그대로 확인(체크 해제하면 다시 보임) |

`Builds/`는 깃에 올리지 않음(.gitignore).

## 플랫폼 실행 설정 ([PlatformRuntime.cs](../Assets/_Project/Scripts/Meta/PlatformRuntime.cs))

- 모바일: 60프레임 · 화면 꺼짐 방지 · 가로 화면 고정 / PC: 수직 동기화
- **뒤로 가기**(안드로이드 뒤로 버튼 · PC Esc): 맨 위 창 `닫기` → 화면 `← 뒤로` → 홈 · 타이틀이면 '게임 종료' 확인. 알림 창이 떠 있거나 전투 중이면 무시. iOS는 해당 없음
- 앱이 백그라운드로 가면 세이브를 디스크에 씀(클라우드는 원래대로 올림)
- 설정 창 `게임 종료`(PC · 안드로이드)
- 전투 기술 버튼: 터치는 **길게(0.4초) 누르면 설명만** 보고 기술은 쓰지 않음(마우스는 올리면 설명)

## PC 화면 설정

설정 ▸ `화면`: **전체 화면 / 창 모드** · 해상도 `< 1920 × 1080 >`(16:9, 모니터보다 큰 것 제외 · 모니터 해상도 포함). 바로 적용, 이 PC에 저장(기기 설정 `display.*`), 다음 실행 때 그대로. 창 모드는 모니터보다 한 단계 작게. 코드: [DisplaySettings.cs](../Assets/_Project/Scripts/Meta/DisplaySettings.cs). 모바일은 해당 없음.

## 데이터 조작 방지(기본)

| 방어 | 내용 |
|---|---|
| 세이브 암호화 · 서명 | 계정 데이터는 PC 레지스트리 · 기기에 **AES 암호화 + HMAC 서명(키 이름 포함)**. 손으로 고치거나 다른 키 값을 옮겨 붙이면 서명이 맞지 않아 그 값을 무시(`SaveStore.TamperCount`), 서버에도 올리지 않음. 옛 평문 세이브는 처음 실행 때 한 번 암호화로 옮김(`__savestore.v` = 2). 기기 설정(소리 · 화면 등)은 평문 |
| Windows IL2CPP | 출시 설정 적용 시 PC도 IL2CPP(게임 코드를 기계어로 — DLL 분해 · 수정이 어려움). **Visual Studio의 'C++를 사용한 데스크톱 개발' 구성 요소 필요** |
| 월드 레이드 기록 검증 | 한 판 상한 6억(`ServerRaid.MaxRunDamage`) · 한 주 상한 = 6억 × 2회 × 7일. 상한을 넘는 다른 플레이어 기록은 순위표 · 공유 체력에서 제외, 내 한 판 기록은 상한으로 자름 |
| 결투장 점수 검증 | 12,000점(`PlayerArena.MaxPlausiblePoints`)을 넘는 플레이어는 순위 · 매칭에서 제외 |
| 공개 프로필 정리 | 다른 플레이어의 캐릭터(레벨 · 성급 · 초월 · 스킬 · 호감도) · 장비(부위당 1개 · 성급 · 강화 · 초월 · 보조 옵션 4개 · 옵션 값 ≤ 굴린 횟수 × 최대 1회 값)를 게임에서 가능한 범위로 자름 → 친선 전투 · 결투장 상대가 비정상으로 강해지지 않음 |

한계: 키가 실행 파일 안에 있어 작정하고 분석하면 뚫을 수 있고, 서버는 여전히 게임이 보낸 세이브를 받습니다. 완전한 방어는 재화 · 뽑기 · 순위를 서버(Cloud Code)가 처리하도록 옮기는 것(출시 뒤 단계). 메모리 변조 툴 대응은 별도(유료 에셋 등).
