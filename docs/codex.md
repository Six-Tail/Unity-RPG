# 캐릭터 도감

홈 왼쪽 아래 **`도감`** 버튼. 게임의 전체 캐릭터(25명)를 한 화면에서 보고, 일러스트를 크게 감상하고, 모은 인원에 따라 **수집 보상**을 받습니다.

## 화면

- **왼쪽 세로 탭**(2026-11 개편): `전체 · 태생 6성 · 5성 · 4성 · 3성`(성급 색 원 · 보유 수), 그 아래 **수집 보상 5단계**(보상 아이콘 · `받기` — 받을 수 있으면 빨간 느낌표).
- **가운데 목록**: 위에 속성 필터(`전체` + 5속성 아이콘), 캐릭터 카드 5열(보유한 캐릭터 먼저). 보유 = 컬러 + 속성 색 빛, **미보유 = 어둡게 + `미보유`**, 왼쪽 위 ★성급 · 오른쪽 위 속성 아이콘. 누르면 목록은 그대로 두고 선택 테두리와 상세만 바뀜.
- **오른쪽 상세**: 선택한 캐릭터의 일러스트 · 이름 · 태생 성급 · 속성/역할 · 획득처 · 보유 정보(레벨 · 돌파 · 현재 성급/초월 · 중복) · 대표 대사.
  - 미보유 캐릭터는 일러스트가 어둡게 나오고 대표 대사는 가려집니다.
  - 보유 캐릭터는 **`크게 보기`** → 전체 화면 감상(화면을 누르면 닫힘).
  - 보유 캐릭터는 **`호감도 Lv.N`** → 호감도 창(선물 · 단계 보상 · 개인 스토리) — [bond.md](bond.md).
- **수집 현황**: 오른쪽 위 `수집 18 / 25  72%`. 홈의 도감 버튼에도 보유 수와 받을 보상 수(`●1`)가 표시됩니다.

## 획득처 표시

배너 구성(`GachaController.Banners`)에서 자동으로 판단합니다.

| 표시 | 조건 |
|---|---|
| 픽업 뽑기 한정 | 어떤 픽업 배너의 픽업 6성이고, 상시 배너 풀에는 없음 |
| 픽업 뽑기 · 상시 뽑기 | 픽업 배너와 상시 배너의 풀에 모두 있음 |
| 상시 뽑기 / 픽업 뽑기 | 한쪽 풀에만 있음 |

## 수집 보상 (계정당 1회)

| 수집 인원 | 보상 |
|---|---|
| 5명 | 크리스탈 100 |
| 10명 | 상시 뽑기권 ×3 |
| 15명 | 크리스탈 300 |
| 20명 | 픽업 뽑기권 ×3 |
| 25명 (전원) | 픽업 뽑기권 ×5 · 크리스탈 500 |

`PlayerCodex.Milestones`에서 조정합니다. 인원 수(`count`)가 세이브 키라, 숫자를 바꾸면 그 단계의 수령 기록이 사라집니다.

## 코드

| 파일 | 역할 |
|---|---|
| [PlayerCodex.cs](../Assets/_Project/Scripts/Meta/Codex/PlayerCodex.cs) | 전체 목록 · 수집 현황 · 획득처 · 수집 보상(`PlayerPrefs("codex")`) |
| [CodexScreen.cs](../Assets/_Project/Scripts/Meta/UI/CodexScreen.cs) | 도감 화면 · 일러스트 크게 보기(코드로 UI 구성) |

- 전체 캐릭터 목록은 `GameDatabase`(로스터가 쓰는 `MainDatabase`)입니다. 캐릭터를 추가하면 도감에도 자동으로 나옵니다.
- 보유 여부는 `PlayerRoster`가 기준입니다.
- 보상 지급은 임무와 같은 `MissionReward.GrantTo`를 씁니다.
- 테스트: `Meta` 오브젝트의 `PlayerCodex` 우클릭 → `수집 보상 기록 초기화`.
- 도감 도입 전에 만든 `Main.unity`도 그대로 동작합니다 — 씬에 `CodexScreen`이 없으면 `ScreenNavigator`가 실행 중에 만들고, `PlayerCodex`가 없으면 로스터 오브젝트에 붙입니다. 메인 씬을 다시 생성하면 둘 다 씬에 들어갑니다.
- 배경은 `Backgrounds/codex` → 없으면 `Backgrounds/growth`(육성 화면 그림)를 씁니다.
